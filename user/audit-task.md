/workbench:config-audit

This is a scheduled, unattended run of the monthly Claude Code config audit. If the line above did not load the workbench config-audit skill's instructions, invoke the `workbench:config-audit` skill with the Skill tool. Follow that skill exactly: read-only, change no setting, hook, skill, plugin, memory file, repo or worktree, never print secrets, tokens or env values, and write only the report at <cfg>/audits/<YYYY-MM>.md, where <cfg> is the Claude Code config folder, {{CONFIG_DIR}}. Recommend at most three actions and apply none of them. Finish with the report's 3-line summary (overall status, worst finding, the one action to take) as your final message.

If no `workbench:config-audit` skill exists, the workbench plugin is not installed, not enabled, or failed to load. Then run these fallback checks instead, with the same read-only rules, and record each as PASS, WARN or FAIL with the number behind it:

1. Plugin: `claude plugin list --json` (or `claude plugin list`). FAIL when workbench@workbench is missing, disabled, or listed with errors ("failed to load"), and FAIL when the workbench marketplace's install location does not exist (the `installLocation` of the `workbench` entry in <cfg>/plugins/known_marketplaces.json, normally <cfg>/workbench-kit); this is the worst finding, because no workbench hook is enforcing anything. Name the file or folder the error points at.
2. Settings parse: `jq empty FILE` on <cfg>/settings.json, on the workbench config ({{WORKBENCH_JSON}}), and on `.claude/settings.json` and `.claude/settings.local.json` in every repo the config lists under `uv_repos` or `repo_groups[].repos` (expand a leading `~/`). FAIL on any parse error. Report the user-level permissions allow, ask and deny counts and the hook events registered in <cfg>/settings.json.
3. `claude doctor </dev/null`. FAIL if its output lists "Invalid settings".
4. Memory: bytes and lines of each `repo_groups[].memory_dir/MEMORY.md` and of every <cfg>/projects/*/memory/MEMORY.md. FAIL above 25,000 bytes or 200 lines (Claude Code stops loading the index past that); WARN above 15,000 bytes.
5. Stray processes: `pgrep -f 'chrome-headless-shell|--remote-debugging-pipe' | wc -l` and `pgrep -f playwright-mcp | wc -l`. WARN on any headless browser while no browser work is running, or on more than 6 MCP processes.
6. Worktrees: `git -C REPO worktree list --porcelain` for each listed repo. List worktrees whose HEAD commit is older than 30 days (`git -C WORKTREE log -1 --format=%cs`) and any marked prunable. List only; never remove or prune anything.

Write <cfg>/audits/<YYYY-MM>.md (create the folder if needed): a 3-line summary at the top (overall status, the worst finding, the one action to take), one table row per check, and at most three recommended actions, the first being to run `bash install.sh --apply` from the workbench checkout (it re-syncs the installed copy in <cfg>/workbench-kit and re-adds the marketplace from it) or `/plugin enable workbench@workbench`. Plain text, no em dashes. Finish with the same 3-line summary as your final message.
